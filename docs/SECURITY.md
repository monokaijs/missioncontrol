# Security model

Use only on a Windows account/computer you own or are explicitly authorized to administer. A trusted local user configures the token, user IDs, private-chat IDs, allowed folders and permissions. There is no first-contact pairing and no remote way to enable permissions. Each incoming message, document and callback must pass both positive-ID allowlists, private-chat type and non-bot sender checks. Inline or inaccessible callbacks, edits and channel/group posts are ignored. Action permissions are checked after identity validation. Window references and output-download capabilities expire in two minutes; output documents are also bound to user/chat and require shell permission.

A local Start creates a fresh worker and discards queued offline updates. Power confirmations use 128-bit Windows CNG random nonces, a steady-clock 30-second deadline, matching user AND chat, and consume-before-execute semantics. Starting a new confirmation for the same peer replaces the previous one. Stop/restart/settings changes clear all confirmations. Each power callback requires current Power permission and authorization again. Cancellation clears all peers' pending power confirmations. Telegram buttons are capabilities only after authorization; no HWND, raw shell command, or absolute remote file path is accepted from callback data.

The token is encrypted using current-user Windows DPAPI with UI forbidden, atomically saved, never placed in logs, and never included in the package. This protects the token at rest against other accounts/offline copies; it does not defend against malware or administrators on the same account/machine. Other settings and user IDs are plaintext. Local activity logs rotate at roughly 1 MiB with one backup; command bodies, filenames/contents and output are not logged. The app is not a tamper-proof audit system. Secrets and output necessarily exist in process memory while in use.

WinHTTP uses system TLS validation and disallows HTTP redirects (avoiding token-bearing URL forwarding). API hosts are fixed to api.telegram.org. No inbound listener. Errors omit full URLs and response bodies. Network failures retry after five seconds; invalid tokens disconnect. A dedicated bot must not have another poller or webhook. Telegram/cloud account security remains part of the trust boundary. Rate limits can delay replies.

Transfer paths are numbered roots plus relative components. Lexical checks reject `..`, empty components, absolute paths, alternate streams, device names, ambiguous trailing dots/spaces and control characters. Unicode is converted strictly. Every existing root/ancestor/subdirectory is opened with `FILE_FLAG_OPEN_REPARSE_POINT` and held without write/delete sharing; every handle is checked for reparse attributes and correct type. Files are opened by handle; hard-linked files are rejected. Reads are capped at 20 MiB; writes use `CREATE_NEW`, exclusive sharing, handle-based partial-file deletion on cancellation/failure, and never invoke a file. Configured roots themselves must be ordinary local directories, not drive roots. A busy or unusual filesystem may be refused. Folder policy assumes Windows correctly enforces handle sharing and local filesystem semantics; kernel drivers, administrators and malicious local privileged actors are out of scope.

**Shell permission bypasses the intent of transfer-root restrictions.** It executes arbitrary single-line cmd syntax under the current account. It is not a sandbox. Commands run hidden to avoid console flashes, but the app/tray/audit remain visible. A Windows Job Object contains the process and descendants, limits active processes to 16, and kills the job on timeout (15s), Stop, output cap (64 KiB) or completion. Only the pipe/NUL handles are inherited through an explicit handle list; no elevation or credentials. Background children cannot persist beyond the job. External effects already performed, writes already completed, network requests already delivered and commands sent to external services cannot be undone by Stop.

No telemetry, stealth installation, service, remote autorun enabling, UAC bypass or security-setting modifications. The startup toggle affects only `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\MissionControl` on a direct local GUI click. The app requests `asInvoker` privileges. Graceful shutdown temporarily enables the current account's existing shutdown privilege; it does not acquire elevation. Before quitting, Stop cancels polling and the running job, joins the action worker, and clears ephemeral capabilities. A small native operation already in progress can complete before Stop returns; no worker survives its return.

Report vulnerabilities privately to the repository owner; do not include tokens, private captures or file contents in public issues.
